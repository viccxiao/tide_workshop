# MLOps on Databricks: hands-on workshop

Build a KYC onboarding risk model end to end: **features, training and registry, deployment, monitoring, and automated approved deployments**.
Everything runs on **synthetic data** in **your own schema**, so nothing touches existing pipelines.

## Get started

1. In your workspace, go to **Workspace → Create → Git folder**
2. Paste `https://github.com/viccxiao/tide_workshop.git` and click **Create Git folder**
3. Open `00_setup`, attach **Serverless** compute, type a catalog you can create schemas in, and click **Run all**

## Notebooks

| Notebook | What you build | Time |
|---|---|---|
| `00_setup` | Your schema, fake KYC data, workspace checks | 3 min |
| `01_feature_engineering` | A documented feature table with lineage, published to the online store | 15 min |
| `02_train_and_register` | Two models tracked in MLflow, registered in Unity Catalog, with a champion | 15 min |
| `03_deploy` (Part A) | A Model Serving endpoint (starts in the background) | 5 min |
| `04_monitoring` | 30 days of predictions and a drift monitor with a dashboard | 15 min |
| `03_deploy` (Part B) | Call the endpoint with just a customer ID | 10 min |
| `05_deployment_job` | A job that tests every new model version, waits for approval, then deploys it | 20 min |
| `99_cleanup` | Remove everything you created | 2 min |

**Order:** 00 → 01 → 02 → 03 Part A → 04 → 03 Part B → 05

Run `05` section by section (not Run all), because you approve the model halfway through.

## Folders

- `pipeline/`: the three tasks of the deployment job (Evaluation, Approval_Check, Deployment) and the model checks they use
- `cicd/`: the code side of CI/CD. The project as a bundle (`databricks.yml`), an example GitHub Actions pipeline and unit tests. See `cicd/README.md`.

## What you need

- Serverless notebooks
- A catalog where you can create a schema
- Permission to create Model Serving endpoints, an online feature store and data quality monitors

`00_setup` checks all of these and shows ✅ / ❌. If the online feature store isn't available, the workshop still works: the endpoint receives features in the request instead.

## The data

All data is generated by `00_setup` and is entirely fictional:

- `customers`: business customers signing up (sector, country, company age, directors, turnover)
- `document_checks`: identity document verification attempts
- `screening_hits`: PEP, sanctions and adverse media hits
- `risk_labels`: outcome of manual risk review

In the last 30 days a new pattern of risky sign-ups appears, which you find in `04_monitoring`.
